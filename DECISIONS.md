# Decisions

### 1. Why this ingestion strategy over the obvious alternative you rejected?

I chose a structured, focused ingestion strategy instead of simply collecting and storing all available user data. The main reason was to keep the system efficient, easier to maintain, and focused on the information that is actually useful for productivity and task management. The alternative of ingesting everything could increase storage and processing requirements and introduce unnecessary or irrelevant data. My approach prioritizes useful information while keeping the system simple and practical.

### 2. One trade-off you made under the time limit, and what you'd do with a real week.

Because of the limited development time, I prioritized the core functionality and user experience over adding more advanced features. Some features could have been made more sophisticated, such as deeper AI personalization, more extensive data processing, and additional productivity analytics. With a full week, I would improve the AI recommendations, add more testing and error handling, optimize performance, and refine the UI based on user feedback.

### 3. Where did you use AI tools, and what did you personally verify or change afterward?

I used AI tools mainly for brainstorming, generating development ideas, improving code structure, debugging errors, and getting suggestions for UI and functionality. However, I personally reviewed and tested the generated code instead of using it blindly. I verified that the features worked correctly, fixed errors, adjusted the implementation according to my project's requirements, and made changes to the UI and logic where necessary. This helped ensure that the final project was actually understood and tested by me.
